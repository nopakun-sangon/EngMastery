หลังจากจบการประชุมใหญ่ประจำเดือนของแผนก พี่กานต์ได้เรียกอาร์เทอร์เข้าไปคุยเป็นการส่วนตัวในห้องกระจกเล็กๆ พร้อมกับยื่นเอกสารประเมินผลการทดลองงานระยะครึ่งทางมาให้ดู

"ขอบคุณครับพี่กานต์" อาร์เทอร์ยิ้มรับ แต่สังเกตเห็นว่าพี่กานต์ยังมีเรื่องสำคัญที่ยังไม่ได้พูด

พี่กานต์เลื่อนโบรชัวร์การสอบที่มีโลโก้รูปรอยยิ้มสีส้มของ Amazon Web Services มาตรงหน้าอาร์เทอร์

"AWS Certified Solutions Architect - Associate (SAA-C03)"

"บริษัทออกค่าสอบที่ราคาเกือบหกพันบาทให้ฟรีในครั้งแรก แต่ถ้าสอบตก... ครั้งต่อไปเราต้องจ่ายเอง และถ้าไม่มีใบนี้ก่อนสิ้นเดือนหน้า HR จะไม่สามารถอนุมัติการบรรจุเป็นพนักงานประจำและปรับฐานเงินเดือนใหม่ให้อาร์เทอร์ได้"

อาร์เทอร์ก้มมองตัวหนังสือบนกระดาษแล้วกลืนน้ำลายลงคออย่างยากลำบาก เขารู้จักชื่อเสียงของข้อสอบใบนี้ดีจากที่ภพกับราจเคยคุยกัน มันคือข้อสอบจำนวน 65 ข้อ ใช้เวลา 130 นาที ที่ไม่ได้ถามแค่ว่าปุ่มนี้คืออะไร แต่โจทย์แต่ละข้อคือ "กรณีศึกษา" ความยาวสามถึงสี่บรรทัดที่เป็นภาษาอังกฤษล้วนๆ!

สำหรับคนที่อ่านภาษาอังกฤษช้าอย่างเขา ลำพังแค่อ่านโจทย์ให้ครบทุกข้อก็น่าจะหมดเวลาแล้ว ยังไม่นับเนื้อหาเรื่องโครงสร้างเครือข่าย (Networking) บนคลาวด์ที่เขาแทบไม่มีพื้นฐานมาก่อนเลย

"ไม่ต้องเครียดเกินไปอาร์เทอร์" พี่กานต์ตบไหล่ให้กำลังใจ "ข้อดีของสายงานเราคือ สิ่งที่อยู่ในข้อสอบ มันก็คือสิ่งที่เราต้องเจอในงานจริงนี่แหละ คืนนี้ลองเริ่มอ่านบทแรกเรื่อง IAM (การจัดการสิทธิ์) กับ S3 (โกดังเก็บไฟล์) ดูก่อน สองเรื่องนี้ออกสอบเยอะมาก"

คืนนั้น หลังจากส่งน้องออกัสเข้านอนเรียบร้อยแล้ว อาร์เทอร์ก็มานั่งเปิดคอร์สเรียนออนไลน์เตรียมสอบ AWS บนโต๊ะกินข้าว โดยมีแพรชงนมอุ่นๆ มาวางไว้ให้ข้างๆ

เขาใช้เวลาเกือบสองชั่วโมงไปกับการจดสรุปเรื่อง AWS S3 (Simple Storage Service) และกฎการให้สิทธิ์ที่ซับซ้อนของ AWS จนตาปรือ

ในคอร์สติวสอนไว้ว่า การที่โปรแกรมตัวหนึ่งจะเข้าไปหยิบไฟล์ในโกดัง S3 ได้นั้น ต้องผ่านด่านตรวจถึง 2 ด่าน คือ:

IAM Role (บัตรประจำตัวผู้ขอ): ตัวโปรแกรมต้องมีสิทธิ์ได้รับอนุญาตให้ออกไปหยิบของ

S3 Bucket Policy (ยามเฝ้าหน้าโกดัง): ตัวโกดังเก็บไฟล์เอง ก็ต้องตั้งกฎอนุญาตให้คนคนนั้นเข้ามาได้ด้วย และถ้ามีกฎข้อไหนเขียนคำว่า Explicit Deny (สั่งห้ามอย่างชัดเจน) เพียงบรรทัดเดียว... ต่อให้มีบัตรผ่านระดับพระเจ้าก็จะถูกปฏิเสธทันที!

"เข้าใจยากชะมัดเลยแฮะ..." อาร์เทอร์นวดขมับตัวเองขณะปิดสมุดโน้ตตอนเกือบเที่ยงคืน โดยไม่รู้เลยว่า ความรู้ที่เขาเพิ่งฝืนอ่านจนปวดหัวเมื่อครู่นี้ กำลังจะได้ใช้ช่วยชีวิตงานจริงในอีกไม่กี่ชั่วโมงข้างหน้า!

อาร์เทอร์กำลังใช้เวลาว่างช่วงเช้าลองทำโจทย์ข้อสอบจำลอง (Practice Exam) เรื่องที่อ่านมาเมื่อคืนไปได้แค่ห้าข้อ เสียงแจ้งเตือนข้อความจาก ‘โคลอี้’ สาวนักพัฒนาฝั่งออสเตรเลียก็เด้งขึ้นมาในห้องแชทของทีม Blue

ภพที่นั่งอยู่ข้างๆ รีบเปิดหน้าจอขึ้นมาเช็กทันที "เดี๋ยวผมดูให้เองครับพี่อาร์เทอร์ เรื่องผูกสิทธิ์พอดใน EKS เข้ากับ AWS (IRSA) ของถนัดผมเลย!"

ภพใช้เวลาไล่เช็กอยู่เกือบสิบห้านาที แต่สีหน้าของรุ่นน้องกลับยิ่งขมวดคิ้วแน่นขึ้นเรื่อยๆ จนต้องหันมาขอความช่วยเหลือจากอาร์เทอร์กับราจ

"แปลกมากเลยครับพี่อาร์เทอร์... ผมเช็กใน AWS EKS แล้ว พอดตัวนี้ก็ผูกกับ IAM Role ที่ชื่อว่า invoice-s3-writer ถูกต้องแล้วนะ แถมใน Role นั้น ผมก็ให้สิทธิ์ s3:PutObject (อนุญาตให้วางไฟล์) เต็มที่เลย แล้วทำไมเวลามันเอาไฟล์ไปวางใน S3 ถึงยังโดนด่าว่า Access Denied ได้ล่ะครับเนี่ย?"

ราจที่นั่งอยู่ถัดไปชะโงกหน้ามาดู "ลองสั่งรีสตาร์ทพอดใน Argo CD หรือยังภพ บางทีมันอาจจะยังจำค่าสิทธิ์เก่าอยู่นะ"

"รีสตาร์ทไปสามรอบแล้วครับพี่ราจ ก็ยังโดน 403 เหมือนเดิม โคลอี้กำลังรอเอาฟีเจอร์นี้ขึ้น Production บ่ายนี้ด้วยสิ ทำไงดีเนี่ย..." ภพเริ่มลนลาน

อาร์เทอร์ที่นั่งฟังอยู่เงียบๆ รู้สึกเหมือนมีกระแสไฟฟ้าแล่นผ่านสมอง... มีบัตรผ่าน IAM Role ถูกต้องแล้ว... แต่ยังเข้าโกดัง S3 ไม่ได้ และโดนฟ้องว่า Access Denied?

ภาพแผนผังที่เขาเพิ่งวาดลงในสมุดโน้ตเตรียมสอบเมื่อคืนตอนห้าทุ่ม ลอยขึ้นมาในหัวอย่างชัดเจน!

"ภพ..." อาร์เทอร์เอ่ยขึ้นพร้อมกับเลื่อนเก้าอี้เข้าไปใกล้ "เมื่อกี้ภพเช็กแค่ฝั่ง IAM Role (บัตรประจำตัวของพอด) อย่างเดียวใช่ไหม? แล้วภพได้ไปเช็กกฎของ 'ยามเฝ้าหน้าโกดัง' หรือตัว S3 Bucket Policy ของถังเก็บไฟล์ใบใหม่นั้นหรือยัง?"

ภพกะพริบตาปริบๆ "S3 Bucket Policy เหรอครับ? ปกติถ้าเราให้สิทธิ์ที่ IAM Role แล้ว มันก็ควรจะเข้าได้เลยไม่ใช่เหรอครับพี่?"

"ไม่เสมอไปครับ" อาร์เทอร์ตอบด้วยน้ำเสียงมั่นใจ เพราะเพิ่งทำข้อสอบจำลองข้อนี้ผิดมาหมาดๆ เมื่อสิบนาทีที่แล้ว! "เมื่อคืนพี่เพิ่งอ่านเจอในหนังสือเตรียมสอบ AWS Cert มา... เขาบอกว่าถ้าที่หน้าถัง S3 มีการตั้งกฎ Bucket Policy บังคับไว้ ต่อให้พอดของเรามีบัตรผ่านถูกต้อง แต่ถ้าทำผิดเงื่อนไขของยามเฝ้าถัง มันจะสั่ง Explicit Deny (ห้ามเข้าเด็ดขาด) ทันที ไหนภพลองเปิดหน้าตั้งค่าของถัง S3 ใบนั้นให้พี่ดูหน่อยสิ"

ภพรีบคลิกเปิดหน้า AWS Console ไปที่บริการ S3 แล้วเปิดแท็บ Bucket Policy ของถังเก็บใบเสร็จขึ้นมาบนจอทันที

บนหน้าจอปรากฏโค้ด JSON ยาวเหยียดที่ทีมสีเขียว (Green Team) ของเอเลน่าเป็นคนตั้งค่ามาตรฐานความปลอดภัยเอาไว้ สายตาของอาร์เทอร์กวาดอ่านไปทีละบรรทัด จนกระทั่งไปสะดุดเข้ากับย่อหน้าสุดท้าย!

JSON


"Effect": "Deny",
"Principal": "*",
"Action": "s3:PutObject",
"Condition": {
    "StringNotEquals": {
        "s3:x-amz-server-side-encryption": "aws:kms"
    }
}
"เจอแล้ว!" อาร์เทอร์ชี้ไปที่หน้าจอด้วยความตื่นเต้น "ดูตรงบรรทัด Condition (เงื่อนไข) นี่สิภพ! ยามเฝ้าถัง S3 ใบนี้ถูกเอเลน่าตั้งกฎเหล็กเอาไว้ว่า 'สั่งห้าม (Deny) ทุกคนเอาไฟล์มาวาง ถ้าไฟล์นั้นไม่ได้ระบุว่าจะเข้ารหัสความปลอดภัยด้วยกุญแจ KMS'!"

ราจที่ชะโงกหน้ามาดูด้วยถึงกับตบเข่าฉาด "Oh! Brilliant, Arthur! That's a classic AWS security policy! Because invoices contain customer personal data, Green Team enforced KMS encryption on the bucket! Chloe's code is trying to upload the PDF without the encryption header!"(โอ้! ยอดเยี่ยมมากอาร์เทอร์! นั่นคือกฎความปลอดภัยคลาสสิกของ AWS เลย! เพราะใบเสร็จมีข้อมูลส่วนตัวของลูกค้า ทีมสีเขียวเลยบังคับให้ต้องเข้ารหัสไฟล์ โค้ดของโคลอี้พยายามอัปโหลดไฟล์โดยไม่ได้แนบคำสั่งเข้ารหัสมาด้วย มันเลยโดนปฏิเสธ!)

"โห... พี่อาร์เทอร์ตาเทพมาก! ถ้าพี่ไม่บอกให้มาดูหน้านี้ ผมคงงมอยู่ใน EKS ไปอีกครึ่งวันแน่ๆ!" ภพมองรุ่นพี่ด้วยสายตาเลื่อมใสสุดๆ

"พี่ไม่ได้ตาเทพหรอกภพ พี่แค่เพิ่งโดนหลอกในข้อสอบจำลองเมื่อกี้เอง" อาร์เทอร์หัวเราะเบาๆ ก่อนจะหันกลับไปที่เครื่องของตัวเองเพื่อจัดการแก้ปัญหาให้จบครบวงจร

แต่การแก้ปัญหานี้ต้องทำ 2 ส่วน คือ:

บอกให้ โคลอี้ เติมคำสั่งเข้ารหัสไฟล์ในโค้ดของเธอ (หรือตั้งค่า Default Encryption ที่ถัง)

และที่สำคัญที่สุดตามหลักการในหนังสือสอบ... อาร์เทอร์ต้องเข้าไปเพิ่มสิทธิ์ใน IAM Role ของพอด ให้สามารถใช้งาน "กุญแจเข้ารหัส (KMS Key)" ตัวนั้นได้ด้วย (kms:GenerateDataKey) ไม่อย่างนั้นพอโคลอี้แก้โค้ดเสร็จ ก็จะติดล็อกกุญแจอยู่ดี!

อาร์เทอร์แก้ไขไฟล์ตั้งค่าสิทธิ์ IAM ของระบบ ส่งขึ้น GitHub Actions เพื่ออัปเดตระบบและซิงค์กับ Argo CD อย่างคล่องแคล่ว จากนั้นเขาก็พิมพ์ข้อความภาษาอังกฤษอธิบายสาเหตุและวิธีแก้ส่งไปให้โคลอี้ใน Slack โดยใช้คำศัพท์เทคนิคที่เพิ่งอ่านมาจากหนังสือสอบเมื่อคืนได้อย่างเป็นธรรมชาติ:

Hi Chloe, I found the root cause. The S3 Bucket Policy has an Explicit Deny if the upload request does not include KMS Server-Side Encryption.
I have updated our EKS Pod's IAM Role to allow using the KMS key. Please add the header x-amz-server-side-encryption: aws:kms to your S3 upload code and try again!

"ครับพี่กานต์!" อาร์เทอร์ยิ้มกว้างด้วยความตื่นเต้น "ตอนอ่านในหนังสือผมก็นึกภาพตามไม่ค่อยออกหรอกครับว่าทำไมมันต้องแยกด่านตรวจให้วุ่นวายขนาดนี้ แต่พอมาเจอของจริงในงานวันนี้... ผมเข้าใจทะลุปรุโปร่งเลยครับ!"

ความกลัวเรื่องการสอบใบเซอร์ AWS ที่เคยกดทับอยู่ในใจเมื่อวาน ค่อยๆ เบาบางลงไป

อาร์เทอร์ค้นพบเคล็ดลับการเรียนรู้ในวัยสามสิบของตัวเองแล้ว... เขาไม่จำเป็นต้องท่องจำตำราหนาๆ แบบนกแก้วนกขุนทองเหมือนสมัยเรียนมหาวิทยาลัย แต่เขาจะใช้ "งานจริงตรงหน้า" นี่แหละ เป็นห้องแล็บสำหรับเตรียมสอบที่ดีที่สุด!
