บทที่ 4: ย่อหน้ามรณะกับด่านตรวจของเอเลน่า

"หนึ่ง... สอง... เคาะวรรคสองที แล้วค่อยพิมพ์คำว่า steps:"

อาร์เทอร์พึมพำกับตัวเองเหมือนคนกำลังท่องคาถา ดวงตาทั้งสองข้างจ้องเขม็งไปที่หน้าจอโปรแกรมเขียนโค้ด (VS Code) ซึ่งมีเส้นประแนวตั้งจางๆ เรียงรายอยู่เต็มหน้าจอ

บ่ายวันพุธแล้ว ตลอดครึ่งเช้าที่ผ่านมา อาร์เทอร์ได้ค้นพบสัจธรรมข้อใหม่ของโลก DevOps... นั่นคือสิ่งที่น่าปวดหัวกว่าการจำคำศัพท์ภาษาอังกฤษ คือการเขียนไฟล์ที่ชื่อว่า YAML!

สมัยที่เขาเป็นโปรแกรมเมอร์ยุคเก่า เวลาเขียนโค้ดภาษาอื่น จะเคาะวรรคกี่ทีหรือขึ้นบรรทัดใหม่ตรงไหนก็ได้ ขอแค่มีเครื่องหมายวงเล็บปีกกา { } ปิดท้ายให้ครบ โปรแกรมก็ทำงานได้ปกติ แต่กับไฟล์ใบสั่งงานของ GitHub Actions ที่เขาต้องเขียนขึ้นมานี้ มันวัดโครงสร้างทุกอย่างด้วย "การเคาะ Spacebar (Indentation)"

เคาะขาดไปหนึ่งช่อง หรือเคาะเกินมาหนึ่งที... ระบบพังทันทีแบบไม่มีการประนีประนอม!

"เอาล่ะ รอบที่ห้า... คราวนี้แหละต้องผ่าน"

อาร์เทอร์สูดหายใจลึก พิมพ์คำสั่ง git push เพื่อส่งไฟล์ใบสั่งงานที่ชื่อว่า deploy.yml ขึ้นไปทดสอบบน GitHub ทันทีที่โค้ดถูกส่งขึ้นไป เมนู Actions บนหน้าเว็บก็เริ่มหมุนติ้วๆ สีเหลือง

เขานั่งลุ้นตัวโก่ง มองดูเครื่องเซิร์ฟเวอร์ชั่วคราวที่ GitHub เสกขึ้นมาทำงานตามใบสั่งของเขา ขั้นตอนที่หนึ่ง ผ่าน... ขั้นตอนที่สอง กำลังแพ็กโค้ดเป็น Docker Image ผ่าน... มาถึงขั้นตอนที่สาม คือการส่งกล่องโค้ดไปเก็บที่โกดังของ AWS (Amazon ECR) ที่ซิดนีย์

ตึ๊ง! เครื่องหมายกากบาทสีแดงเถือกโผล่ขึ้นมาตรงหน้า พร้อมข้อความฟ้องสั้นๆ ว่า:Error: Credentials could not be loaded

"เฮ้อ... ติดเรื่องสิทธิ์การเข้าถึง AWS อีกแล้วแฮะ" อาร์เทอร์ถอนหายใจ ยกมือขึ้นเกาหัวแกรกๆ

จังหวะที่เขากำลังคิดว่าจะเอาคีย์รหัสผ่าน (Access Key & Secret Key) ของ AWS ที่ตัวเองมีอยู่ ไปแปะใส่ไว้ในตั้งค่าของ GitHub ตรงๆ เลยดีไหมเพื่อให้งานเดินต่อได้ เสียงฝีเท้าส้นสูงที่เดินอย่างมั่นใจก็ดังใกล้เข้ามา พร้อมกับกลิ่นน้ำหอมแนวสปอร์ตเย็นๆ

"Are you trying to use long-lived AWS keys in GitHub Actions, Arthur?"(คุณกำลังคิดจะใช้คีย์รหัสผ่านแบบถาวรของ AWS ใน GitHub Actions เหรอคะ อาร์เทอร์?)

เสียงภาษาอังกฤษสำเนียงยุโรปตะวันออกที่ชัดเจนทุกพยางค์และเย็นยะเยือกดังขึ้นจากด้านหลัง อาร์เทอร์สะดุ้งสุดตัว รีบหันเก้าอี้กลับไปมอง

หญิงสาวร่างสูงโปร่งผมสีบลอนด์สว่างมัดรวบตึง ใบหน้าคมเข้มเรียบนิ่งในชุดเสื้อเชิ้ตสีดำสนิท กำลังยืนกอดอกมองหน้าจอของเขาอยู่... ‘เอเลน่า’ (Elena) หัวหน้าทีมสีเขียว (Green Team) ผู้คุมกฎเหล็กด้าน Security ของบริษัทนั่นเอง!

ข้างหลังเอเลน่า ภพที่นั่งอยู่โต๊ะถัดไปแอบทำท่าปาดคอตัวเองพร้อมทำหน้าสยองส่งซิกมาให้อาร์เทอร์

"อะ... เอ่อ... Hi, Elena." อาร์เทอร์ลิ้นพันกัน รีบขยับตัวนั่งหลังตรงแหน่วเหมือนทหารเกณฑ์เจอครูฝึก "I want to push... Docker image to AWS ECR. But it says error."

เขาพยายามเรียงประโยคเท่าที่นึกออก เหงื่อเริ่มซึมตามไรผมเมื่อสบตากับดวงตาสีฟ้าคมกริบของเธอ

เอเลน่าขยับเข้ามาใกล้ ชี้ปลายนิ้วเรียวไปที่หน้าจอของอาร์เทอร์

"In our company, we strictly forbid putting static AWS Access Keys into GitHub." เธอพูดช้าลงนิดหน่อยเมื่อเห็นอาร์เทอร์ตั้งใจฟัง แต่คำศัพท์ที่ตามมากลับทำให้อาร์เทอร์มึนตึ้บ "If someone hacks GitHub, they get our keys forever. You must use OIDC (OpenID Connect) to assume an IAM Role dynamically. No static keys allowed. That's the Green Team policy."

อาร์เทอร์กะพริบตาปริบๆ สมองของเขาจับใจความได้แค่ว่า ห้ามเอาคีย์รหัสผ่านไปใส่ใน GitHub เด็ดขาด เพราะถ้าโดนแฮกจะจบเห่... ให้ไปใช้อะไรสักอย่างที่ชื่อว่า โอ-ไอ-ดี-ซี แทน!

"โอ-ไอ-ดี-ซี...?" อาร์เทอร์ทวนคำเสียงเบา

"Yes, OIDC." เอเลน่าพยักหน้าครั้งหนึ่ง ก่อนจะหยิบปากกาเมจิกบนโต๊ะของอาร์เทอร์ขึ้นมาเขียนตัวอักษรภาษาอังกฤษตัวใหญ่ๆ ลงบนกระดาษโน้ตให้เขา

GitHub OIDC -> AWS IAM Role (Temporary Token)

"Look up this keyword in our internal Confluence wiki. I wrote a security guide about it last month. Once you write the config, send a Pull Request to Green Team for approval."(ลองค้นหาคีย์เวิร์ดนี้ในเว็บคู่มือภายในบริษัทดูนะคะ ฉันเขียนคู่มือความปลอดภัยเรื่องนี้ไว้เมื่อเดือนก่อน พอเขียนคอนฟิกเสร็จแล้ว ส่งคำขออนุมัติมาให้ทีมสีเขียวตรวจด้วย)

พูดจบ สาวสายเฮี้ยบก็วางปากกาลง หมุนตัวเดินกลับไปยังโซนของทีมสีเขียวอย่างสง่างาม ทิ้งให้อาร์เทอร์นั่งถือกระดาษโน้ตแผ่นนั้นค้างอยู่กลางอากาศ

"รอดตายหวุดหวิดนะครับพี่อาร์เทอร์!" ภพรีบไถลเก้าอี้เข้ามาหาทันทีที่เอเลน่าเดินพ้นระยะ "ดีนะพี่ไม่เผลอเอา Access Key ไปใส่แล้วกดรัน ไม่งั้นสัญญาณเตือนภัยที่จอของเอเลน่าดังปี๊บๆ แล้วโดนสั่งล็อกแอ็กเคานต์แน่ๆ!"

พี่กานต์ที่นั่งฟังอยู่ตั้งแต่ต้นหัวเราะในลำคอเบาๆ "บอกแล้วว่าด่านข้อที่ 3 ของเอเลน่านี่แหละของจริง... แต่เขาก็ใจดีนะอุตส่าห์เดินมาเขียนคีย์เวิร์ดให้ ปกติถ้าเป็นคนอื่นทำผิดกฎ เขาแค่ส่งลิงก์กฎระเบียบมาในแชทสั้นๆ แค่นั้นแหละ"

อาร์เทอร์ก้มมองลายมือเฉียบคมของเอเลน่าบนกระดาษ "พี่กานต์ครับ ไอ้เจ้า OIDC ที่คุณเอเลน่าบอกเนี่ย... ถ้าแปลเป็นภาษาชาวบ้าน มันคืออะไรเหรอครับ?"

"เปรียบเทียบง่ายๆ นะอาร์เทอร์" พี่กานต์หมุนเก้าอี้มาอธิบาย "การเอา Access Key ไปใส่ไว้ใน GitHub มันเหมือนกับอาร์เทอร์ปั๊ม 'กุญแจบ้านตัวจริง' เอาไปฝากไว้ที่ป้อมยามหน้าหมู่บ้าน ถ้าวันไหนโจรปล้นป้อมยาม โจรก็ได้กุญแจบ้านเราไปไขเข้าบ้านได้ตลอดกาลถูกไหม?"

"อ๋อ... เข้าใจแล้วครับ แบบนั้นอันตรายจริงด้วย" อาร์เทอร์พยักหน้าหงึกๆ

"ส่วน OIDC ที่เอเลน่าให้ใช้เนี่ย มันคือระบบยืนยันตัวตนแบบไม่ต้องใช้กุญแจถาวร" พี่กานต์ชี้ไปที่คำว่า Temporary Token บนกระดาษ "ทุกครั้งที่ GitHub Actions เริ่มทำงาน มันจะเดินไปบอก AWS ว่า 'เฮ้ ฉันมาจากโปรเจกต์ของทีม Blue ตัวจริงนะ ขอบัตรผ่านชั่วคราวหน่อย' พอ AWS ตรวจสอบว่าใช่ตัวจริง ก็จะออก 'บัตรผ่านชั่วคราวที่มีอายุแค่ 15 นาที' มาให้ พอส่งกล่องโค้ดเข้าโกดังเสร็จ บัตรนั้นก็หมดอายุทันที... โจรขโมยไปก็เอาไปทำอะไรต่อไม่ได้"

ดวงตาของอาร์เทอร์เป็นประกายวาววับขึ้นมาทันที การเปรียบเทียบของพี่กานต์ทำให้เรื่องยากๆ ที่ดูเหมือนภาษามนุษย์ต่างดาว กลายเป็นเรื่องที่สมเหตุสมผลและน่าทึ่งมาก!

"สุดยอดเลยครับพี่... ไม่ต้องมีกุญแจให้หาย เพราะใช้วิธีออกบัตรชั่วคราวเอา!"

เมื่อเข้าใจหลักการแล้ว ความกลัวก็มลายหายไป อาร์เทอร์รีบเปิดหน้าเว็บคู่มือของบริษัท (Confluence) พิมพ์ค้นหาบทความที่เอเลน่าเป็นคนเขียนไว้ บทความนั้นยาวเหยียดและเป็นภาษาอังกฤษล้วนๆ แต่อาร์เทอร์ไม่ย่อท้อ เขาใช้เวลาช่วงบ่ายค่อยๆ แกะทีละย่อหน้า จดคำศัพท์ใหม่อย่างคำว่า Authentication (การยืนยันตัวตน), Assume Role (การสวมบทบาทรับสิทธิ์), และ Trust Policy (นโยบายความเชื่อถือ) ลงในสมุดโน้ต

เขาค่อยๆ แก้ไขไฟล์ YAML ของตัวเองอย่างระมัดระวัง นับช่องไฟการเคาะวรรคทุกบรรทัด และส่งคำขอเชื่อมต่อไปให้ทีมสีเขียวอนุมัติตามขั้นตอนเป๊ะๆ

เวลา 16:45 น.

แจ้งเตือนจากระบบเด้งขึ้นมาว่า Elena approved your pull request. (เอเลน่าอนุมัติคำขอของคุณแล้ว)

มือของอาร์เทอร์แทบจะสั่นด้วยความตื่นเต้น เขากลับไปที่หน้าต่างโค้ดของตัวเอง แล้วกดสั่งให้ GitHub Actions เริ่มทำงานอีกครั้ง!

คราวนี้ ทั้งพี่กานต์และภพต่างก็ชะโงกหน้ามาช่วยลุ้นอยู่ข้างหลังเก้าอี้ของอาร์เทอร์

วงล้อสีเหลืองบนหน้าจอหมุนติ้วๆ...

Set up job -> เครื่องหมายถูกสีเขียว ✅

Configure AWS Credentials via OIDC -> หมุนอยู่สามวินาที... แล้วเปลี่ยนเป็น เครื่องหมายถูกสีเขียว ✅!

Build and Push Docker Image to Sydney ECR -> ตัวเลขเปอร์เซ็นต์การอัปโหลดวิ่งขึ้นอย่างรวดเร็ว... จนกระทั่งจบที่คำว่า Post Build: SUCCESS พร้อมเครื่องหมายถูกสีเขียวดวงใหญ่ ✅!

"เฮ้ยยยย ผ่านแล้วพี่อาร์เทอร์! สีเขียวทั้งกระดานเลย!" ภพร้องเสียงหลง ตบไหล่รุ่นพี่วัยสามสิบดังป้าบ

"เก่งมากอาร์เทอร์! เขียน Workflow ตัวแรกพร้อมผูก OIDC ผ่านได้ในวันเดียว ไม่ธรรมดาเลยนะเรา" พี่กานต์ยิ้มกว้างอย่างภูมิใจ

อาร์เทอร์เอนหลังพิงพนักเก้าอี้ ถอนหายใจออกมาด้วยความโล่งอก รอยยิ้มกว้างปรากฏขึ้นบนใบหน้า ความเหนื่อยล้าจากการนั่งนับช่องไฟและแปลเอกสารภาษาอังกฤษมาทั้งวัน หายไปเป็นปลิดทิ้งเมื่อเห็นเครื่องหมายถูกสีเขียวเรียงกันสวยงามบนหน้าจอ

เขาหันไปมองทางโซนของทีมสีเขียว เห็นเอเลน่าที่กำลังจะลุกไปกดน้ำหันมาสบตาเขาพอดี สาวสายเฮี้ยบหน้านิ่งไม่ได้พูดอะไร แต่เธอพยักหน้าให้เขาครั้งหนึ่งพร้อมรอยยิ้มบางๆ ที่มุมปาก แทนคำยอมรับว่าเขาผ่านด่านตรวจของเธอแล้ว

อาร์เทอร์เหลือบมองนาฬิกาที่มุมจอ... 17:15 น.

วันนี้เขามีกำไรเวลาเหลือตั้งสิบห้านาทีก่อนเลิกงาน! คุณพ่อลูกหนึ่งรีบเปิดสมุดโน้ตขึ้นมาจดสรุปขั้นตอนการทำ GitHub Actions ที่เพิ่งสำเร็จไปสดๆ ร้อนๆ เก็บไว้เป็นคัมภีร์ประจำตัว

เพราะเขารู้ดีว่า... นี่เป็นเพียงก้าวแรกของการโละคุณปู่ Jenkins เท่านั้น ในวันพรุ่งนี้ เขายังต้องเอาเจ้า GitHub Actions ตัวนี้ ไปผูกเข้ากับเจ้าปลาหมึกสีส้ม Argo CD เพื่อให้ระบบทั้งหมดทำงานสอดประสานกันแบบอัตโนมัติ 100% ให้จงได้!
